# Changelog

All notable changes to `umbra-blue` are documented here. Versions follow [Semantic Versioning](https://semver.org/), where breaking changes mean skill renames, removals, or category restructures.

## [Unreleased]

### Added

- **`detect-netexec`, the last claude-red gap.** A new Tier 2 skill in `active-directory` answers claude-red's `offensive-netexec`, so all 79 claude-red skills are now paired (81 pairings, 78 umbra-blue skills: 10 Tier 1, 68 Tier 2). It gives the defender's method for NetExec, the maintained successor of CrackMapExec: SMB password spraying and pass-the-hash ([T1110.003](https://attack.mitre.org/techniques/T1110/003/), [T1550.002](https://attack.mitre.org/techniques/T1550/002/)), remote execution through wmiexec, mmcexec, atexec and smbexec, and SAM, LSA, LSASS and NTDS credential theft ([T1003](https://attack.mitre.org/techniques/T1003/)). Three detections, in prose, key on NetExec's own templates in System 7045, Security 4698 and process creation, with an NTLM fan-out hunt on an empty workstation name. It records where older rules lose coverage: the SigmaHQ CrackMapExec and Impacket rules miss NetExec's smbexec service and default wmiexec command line and the atexec task from v1.5.0 on, and the SigmaHQ secretsdump file rules, which look under `System32`, miss both SAM/LSA dump modes. It lists the SigmaHQ rules and Defender for Identity alerts to run beside them, with tuning, triage, a threat hunt, hardening and limitations. No UMBRASEC rule ships with it: the match logic was checked only against synthetic events built from NetExec, CrackMapExec and Impacket source, not a capture. `tools/pairs.json` no longer lists an unanswered skill, and the README and `PRINCIPLES.md` again say umbra-blue mirrors every claude-red skill.
- **Endpoint rules for hijacked AI coding agents.** `defend-ai-agents` now inlines three new sigma-pack files byte for byte, in a new detection section for coding agents that have no tool-call telemetry. `ai-agent-cli-headless-approval-bypass.yml` fires when an agent CLI (Claude Code, Gemini CLI, Codex, Copilot CLI, Amazon Q) is started headless with its approval prompts off, the way the Nx s1ngularity packages started installed agents in August 2025. `ai-agent-shell-risky-command.yml` fires when a shell the agent started names a credential source or pipes a download into a shell ([T1059](https://attack.mitre.org/techniques/T1059/), [T1552.001](https://attack.mitre.org/techniques/T1552/001/), [T1105](https://attack.mitre.org/techniques/T1105/)). `editor-terminal-risky-command.kql` is a Defender XDR hunt over the VS Code integrated terminal on Windows, where an agent's commands look like a person's. The skill's sentence that no canonical rule exists for this surface now says the endpoint rules exist and the tool-call rules stay the preferred signal, and it adds tuning, a limitation, the ATT&CK techniques and the writeup [What a Hijacked AI Coding Agent Leaves in Your Logs](https://umbrasec.dev/research/detecting-hijacked-ai-coding-agents.html).
- **Blue Team Mapper links.** Every skill now links to its page in the [Blue Team Mapper](https://umbrasec-labs.github.io/BlueTeamMapper/), which shows the skill's techniques and any UMBRASEC rules for them. For techniques in the mapper matrix, the page also shows the matrix rows, the response flow chains, and the reader's own coverage. The link appears in a new Mapper column in the README skill index and in `COVERAGE.md`, and as a `mapper` URL field on each skill in `claude-skills.json`. `tools/build_manifest.py` generates all three from one base URL.
- **Metabase burst rule and egress query.** `detect-metabase-sqli` now inlines two new sigma-pack files byte for byte. `metabase-reset-password-burst.yml` is a Sigma `event_count` correlation: ten or more requests to `/api/session/reset_password` from one client address in ten minutes, the writeup's own dial. It reads no payload, so it also counts an exploit carried in the POST body, the gap the request-line markers rule cannot close. `metabase-egress-inversion.kql` reads firewall logs in `CommonSecurityLog` and flags a day of outbound bytes from the Metabase host at a multiple of its own 14-day median ([T1567](https://attack.mitre.org/techniques/T1567/)). The two prose hunts they replace now cover what the rules cannot (slower sources, extraction split across days), and the skill adds tuning and limitations for both, including the undocumented byte direction of `SentBytes` and `ReceivedBytes`.

### Changed

- **Re-synced the agent coverage for Cursor, Devin and Copilot.** `tools/sync_rules.py` refreshed the three coding agent files in `defend-ai-agents`, and the skill prose that described the old coverage now matches. `ai-agent-cli-headless-approval-bypass.yml` adds the Cursor CLI (`--force`, `-f`, `--yolo`), the Devin CLI (`--permission-mode dangerous`, `yolo` or `bypass`) and the Copilot CLI's bare `--allow-tool` shell grant; a Copilot run with only `--allow-all-tools` or `COPILOT_ALLOW_ALL` is still not covered. `ai-agent-shell-risky-command.yml` adds the Copilot CLI's per-command shells (the Microsoft Copilot app excluded), the Cursor CLI and IDE agent wrappers, and the legacy Windsurf Cascade wrapper. `editor-terminal-risky-command.kql` adds shells started by `copilot-runtime`, the Copilot harness in VS Code, with a `Source` column. Cursor and Devin rest on shipped code and vendor docs, Copilot CLI shells on user reports and the Copilot harness on VS Code source, none on a capture; the limitation now names what is still out (Devin Local and Devin CLI shells, Cursor's default Windows PowerShell executor). Both Sigma rules carry `modified: 2026-10-27`.
- **Re-synced four upstream sigma-pack rule fixes.** `tools/sync_rules.py` refreshed every inlined copy, and the skill prose that described the old logic now matches. `metabase-reset-password-sqli.yml` escapes the `/*` comment marker, which Sigma read as a wildcard that matched any query string containing a slash ([umbrasec.dev issue #3](https://github.com/umbrasec-labs/umbrasec.dev/issues/3)), and adds percent-encoded markers for access logs that keep the query string encoded (`detect-metabase-sqli`, `monitor-external-attack-surface`). `litellm-proxy-spawns-shell.yml` adds versioned `python3.9` to `python3.14` parents and `busybox`, `nc.openbsd`, `nc.traditional` and `netcat` children (`detect-litellm-command-injection`). `litellm-stealer-exfil.yml` matches `cs-host` logged with a port or a trailing dot, so the `c-uri` selection is now only for proxies that log the full URL (`detect-litellm-command-injection`, `detect-data-exfiltration`). `kerberoasting-spn-fanout.yml` gains a `falsepositives` section for scanners, monitoring accounts and busy legitimate accounts (`detect-kerberoasting`).
- **Re-synced seven sigma-pack audit fixes.** `tools/sync_rules.py` refreshed every inlined copy (8 blocks in 4 skills), and the tuning prose that described the old logic now matches. `kerberoasting-rc4-service-ticket.yml` ships with its `TicketOptions: '0x40810000'` constraint commented out, as the tuning note already advised; `kerberoasting-spn-fanout.yml` sets `level: medium`; `kerberoasting-honeypot-spn.yml` drops the invalid `attack.deception` tag (`detect-kerberoasting`). `oauth-consent-sensitive-scopes.kql` strips the JSON quotes from `IsAdminConsent`, so the admin-consent branch can match, and both it and `app-role-assignment.kql` fall back to the app's display name for a service-principal actor (`detect-oauth-consent-phishing`). `litellm-stealer-exfil.yml` anchors the `c-uri` fallback at the host boundary, so `//litellm.dev.evil.example` no longer matches, while a trailing-dot host or a URL with no path still does (`detect-litellm-command-injection`, `detect-data-exfiltration`). `litellm-proxy-spawns-shell.yml` adds `python3.7` and `python3.8` parents (`detect-litellm-command-injection`). The five changed Sigma rules carry `modified: 2026-10-25`.
- **Re-synced the svchost rule for ATT&CK v20.** `masquerading-svchost-outside-system32.yml` now tags `attack.stealth` instead of `attack.defense-evasion`, because ATT&CK v19 (2026-04-28) split the Defense Evasion tactic into Stealth and Defense Impairment and T1036.005 sits under Stealth, and carries `modified: 2026-10-25`. The technique, T1036.005, is unchanged. `tools/sync_rules.py` refreshed its one inlined copy (`detect-ncentral-post-exploitation`).
- **Inlined the OAuth app-credential query.** `detect-oauth-consent-phishing` now ships the sigma-pack's fourth OAuth query, `app-credential-added.kql`, byte for byte: a new client secret or certificate on an application or service principal, the persistence step after consent phishing ([T1098.001](https://attack.mitre.org/techniques/T1098/001/)). The skill adds its tuning (rotation, SAML signing certificates, the `OnServicePrincipal`, `ByApp` and `FirstCredential` triage order), three limitations from the writeup, the Microsoft sources, and T1098.001 in its description, so the Blue Team Mapper links the rule to the skill. The query's header still says "follow-on" rather than "detection 4 of 4", as the sigma-pack has it; `tools/sync_rules.py` refreshed nothing else, as no other inlined rule changed.
- **Migrated skill ATT&CK references to v20.** Techniques that ATT&CK v19 revoked now cite their replacements, with matching links and names: T1562.001 becomes T1685 Disable or Modify Tools, T1562.006 folds into T1685, T1562.002 becomes T1685.001, T1562.008 T1685.002, T1562.010 T1689 Downgrade Attack, T1070.001 T1685.005 and T1070.002 T1685.006 (`detect-edr-evasion`, `detect-redteam-ttps`, `verify-exploit-mitigations`, `defensive-reporting`, `detect-anti-forensics`, `detect-cloud-attack-paths`, `harden-tls`). T1656 Impersonation becomes T1684.001 (`defend-social-engineering`), Mobile T1540 Code Injection, revoked in an earlier release, becomes T1631 Process Injection (`harden-mobile-apps`), and ICS T0857, T0839, T0812 and T0855 become T1693.001, T1693.002, T1694.001 and T1692.001 (`harden-iot`). T1211 is now named Exploitation for Stealth and T1557.001 Name Resolution Poisoning and SMB Relay, and tactics named in prose use Stealth and Defense Impairment instead of Defense Evasion. `defend-ai-agents` and `defend-llm-top-10` add the new v20 techniques T1698 Indirect Prompt Injection, T1699 Direct Prompt Injection and T1700 AI-Enabled Exfiltration next to their MITRE ATLAS references. D3FEND has not yet mapped the v19 IDs, so the D3FEND references in `detect-anti-forensics`, `defensive-reporting` and `detect-edr-evasion` keep the old IDs with a note.

### Fixed

- **ATLAS technique name.** `defend-ai-agents` now cites AML.T0053 by its current MITRE ATLAS name, AI Agent Tool Invocation (ATLAS 2026.09), instead of the old LLM Plugin Compromise. The ID and the link are unchanged.
- **Installer.** An option given without a value (`./install.sh --target`) crashed with `$2: unbound variable`, and `--target --dry-run` took `--dry-run` as the folder. Both now stop with "needs a value" and the usage, as does any value starting with a dash (give such a folder as `./-name`). An install now also removes umbra-blue skills that were renamed or dropped since the last install, whatever the filters, and `--dry-run` lists them. The `.umbra-blue` marker now records `<category>/<skill>`, and only a folder whose marker names that same folder is removed, so a copy you made under another name is kept. Markers written by the older installer hold only the category and are never pruned; an install rewrites them for every skill still in umbra-blue. `--uninstall` now applies the same rule: it used to remove every folder with a marker, so a skill you copied under another name and edited was deleted with the rest. It now keeps such a copy and reports it (`keep my-copy (a copy of web/detect-xss under another name)`). Folders with an older category-only marker are still removed, as they cannot be told apart from the original.
- **Installer help.** `./install.sh --help` printed a fixed line range of the script's header, which had grown past it, so the `--list` and `--dry-run` lines were missing. It now prints the whole header comment, up to the first blank line, and a test checks every usage line is shown.
- **Validator.** `tools/validate.py` now enforces rules that `CONTRIBUTING.md` already stated: only `name` and `description` in the frontmatter, no angle brackets in a description, no `claude` or `anthropic` in a name, and no dashes in any file a skill ships, not just `SKILL.md`. It also catches what the tools silently skipped: a skill folder with no `SKILL.md`, a `SKILL.md` at the wrong depth, one skill name in two categories (the installer would keep only one), an empty `description:` (read as the text "None"), relative links without a `./` prefix, links that leave the repository, and two sigma-pack rules with the same file name (`tools/sync_rules.py` now refuses those too, and both tools read `.yml`, `.yaml` and `.kql` rules through one loader). Malformed YAML frontmatter is reported instead of crashing the run.
- **Tests.** `tools/test_tooling.py` covers the installer and validator on throwaway fixtures, and CI runs it.
- **claude-red coverage count.** claude-red has 79 skills, not 78. It added `offensive-netexec` (active-directory) on 2026-09-13, before 0.1.0, and no umbra-blue skill answers it yet: `detect-ad-credential-abuse` covers AS-REP roasting, DCSync, ACL and delegation abuse, not the spraying, pass-the-hash and remote execution at NetExec's core. `tools/pairs.json` now records 79 upstream skills and lists the unanswered one, `COVERAGE.md` says 80 pairings cover 78 of the 79 and names the gap, and the README and `PRINCIPLES.md` no longer claim a full mirror. The README roadmap also no longer says the rule sync runs in CI: CI checks inlined rules against the sigma-pack, and `tools/sync_rules.py` is run by hand. Later in this release `detect-netexec` (see Added) answers `offensive-netexec`, so `tools/pairs.json` lists no unanswered skill and `COVERAGE.md` shows 81 pairings covering all 79.

## [0.1.0] - 2026-10-23

### Added

- **Full mirror of claude-red.** 77 defensive skills answer all 78 claude-red offensive skills across the same 23 category folders. Two claude-red course skills share a counterpart with their sibling skill.
- **Tier 1, sourced (10 skills).** `detect-kerberoasting`, `detect-oauth-consent-phishing`, `detect-litellm-command-injection`, `detect-metabase-sqli`, `detect-ncentral-post-exploitation`, `detect-data-exfiltration`, `detect-supply-chain-compromise`, `monitor-external-attack-surface`, `defend-llm-top-10`, and `defend-ai-agents`. Each is built from a published UMBRASEC writeup or tool. Where a skill inlines a detection, it is reused byte for byte from the UMBRASEC sigma-pack.
- **Tier 2, methodology (67 skills).** Defender's method, log sources, hunt, and hardening for every remaining claude-red skill, with a banner stating that no bespoke UMBRASEC rule ships yet.
- **Tooling.** `tools/build_manifest.py` generates `claude-skills.json`, `COVERAGE.md`, `MINDMAP.md`, and the README index from `tools/pairs.json`. `tools/validate.py` enforces the library rules. `tools/sync_rules.py` refreshes inlined rules from the sigma-pack. CI runs the validator against the live sigma-pack and fails on stale generated files.
- **Installer.** `install.sh` flattens the category tree into the one-folder-per-skill layout Claude Code discovers, with category and tier filters, collision protection, and uninstall.

### Quality

- Every skill passed an adversarial technical review before release. 110 findings were raised and 107 fixed, including wrong integrity-level SIDs, a miscited advisory, and incorrect Sysmon, NPS, GitHub audit-log, and D3FEND identifiers. The other 3 are logic issues in upstream sigma-pack rules, tracked for a fix in the sigma-pack and a re-sync here.
- Every description fits the 1,024-character Agent Skills limit, and every skill uses only the `name` and `description` frontmatter keys.
